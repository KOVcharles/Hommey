# 短输入路由与对话契约修复

修复对象：`docs/bugs/2026-09-16-short-input-unclear-routing.md`。

无待答问题时，`1` 等数字输入直接澄清，零模型调用、零委派、零业务写入，不生成行程卡。已有行程或用户档案中的常驻地不能作为补字段的授权。

## 职责与实现

| 层 | 负责的行为 |
| --- | --- |
| `core/intent_guard.py` | 低成本输入检查；用显式 `allow_short_reply` 接收运行时的绑定判定，不再接受占位上下文字符串 |
| `agent_runtime/dialogue.py` | 保存实际展示的待答字段/选项；仅恢复同会话上一轮、相同行程版本且正在等待回复的问题；统一行程卡资格 |
| `agent_runtime/contracts.py` | `Finish.kind` 区分 answer、ask、clarify、refuse；`PendingInput` 明确字段或编号选项，两者互斥 |
| `agent_runtime/engine.py` | 消费 unclear；执行有依据的变更；将 ask_user/finish 错误动作落实为收敛；按已提交结果控制卡片出口 |
| `agent_runtime/control.py` | 分操作判断有效进展；工具调用成功不等于业务有进展 |
| `agent_runtime/render.py` | 展示实际绑定的字段和选项；clarify 独立展示，不转成行程卡 |
| `core/presentation/trip_intake_document.py` | 只有显式保存依据才显示“已保存”；档案预填不能充当保存依据 |
| `agent_runtime/profiles.py` | 先判断意图，再执行已确定任务，最后按真实结果交付；明确阶段优先级 |

`event-collection` Skill 和技能目录说明同步为运行时自动校验、提交行程；偏好变更仍由主 Agent 调用 `apply_changes` 经同一提交门处理。

## 待答问题

运行时检查点保存 `pending_input`（实际问题、字段或选项、行程版本）。下一轮只从存储层限定的同用户、同会话上一轮恢复；普通历史文本不能创建此状态。换行程版本、转入其他话题、结束或中断上一轮后，旧待答问题不能继续消费数字。

只在明确询问天数时，将 `1` 解释为一天，并通过现有提交门保存。原文仍是 `1`，不伪造“一天”的用户原话；验证器只对运行时绑定的整数天数放行，其他字段继续使用既有原文与日期校验。

编号选项由运行时展示，范围外的数字重新展示原问题，不调用模型。合法编号向模型提供已选标签和原始回复，不直接把选项写入行程或长期偏好。

中文短字段值（例如“北京”“培训”“明天”）在已知待答字段下交给模型结合上下文解释。较长的自然语言仍走语义判断，不把任意自由文本自动存入待答字段。

## 收敛与展示

- `clarify` 有独立终止路径，即使上下文有行程结果，也不被行程卡兜底覆盖。
- 基于专业结果生成行程卡，必须有可用状态、非空行程事实和提交记录。合法 `needs_input` 保留；失败或空结果不生成卡片。
- 明确的“出差”入口仍允许零模型调用展示空表单，标题不声称保存成功。
- 修复 fallback 中空集合 `all(...)` 为真的路径；`prepare_trip_options` 也不能把空状态变成行程任务。
- 空变更的 `ask_user`、任务执行上限的 `finish` 由运行时消费，避免继续让模型重试。子任务连续空报告只使用原有最多两次修复预算，随后转入澄清。
- 缺项收敛保留同轮已经核实的其他查询结果，不丢掉并行天气、制度等结果。
- 首次读取指南保留最多三轮准备宽限，足够主指南及相关参考；宽限不清零已有失败计数。重复读取不享受宽限。
- 主 Agent 尚未委派确定任务时，不提供 `read_skill`；行程已提交但仍缺必填信息时同样关闭该工具。模型即使忽略当轮 schema，执行层也会拒绝越阶段调用。真实模型复验曾暴露“先读五份 Skill 再澄清”的行为，因此阶段优先级同时由工具可用性落实。
- 没有专业结果时不提供读取/丢弃结果、提交变更工具；没有行程事实时不提供完整规划入口。空状态首轮只提供委派与结束，避免把历史文字误当成结果 ID 反复读取。
- 现有精确行程句式解析允许省略“我要/准备”等前缀，例如“去南京出差”“从北京去南京出差”。仍要求整句匹配，混合需求、否定、疑问、时间条件和多个城市不会被截断消费。已知字段直接走原文验证和事务提交，避免先追问而漏存目的地。

## 验证

离线相关回归：243 passed、9 skipped。覆盖运行时、输入校验、上下文、行程收集/恢复、完整行程、车次酒店选项、执行计划/预算、评测和地图集成；跳过项为显式启用的在线测试。

新增 `tests/test_dialogue_routing.py` 覆盖：无待答状态、已有行程但未提问、合法天数、合法/越界编号、短字段、跨会话、版本变化、中间插入其他话题、幂等重放、空报告、失败报告、空变更、独立结果保留及准备预算。

真实模型验收使用 `tests/test_dialogue_routing_live.py`：业务查询、用户档案和写入全部使用内存 fixture；仅模型请求访问配置的模型服务。用例检查路由、Finish 类型、委派角色、写入、卡片和调用上限。加入阶段工具约束后，7 个用例通过，包括两种没有命中固定规则的意图不明表述。

```powershell
$env:HOMMEY_RUN_LIVE_AGENT_TESTS='1'
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_dialogue_routing_live.py -q
```

真实模型样本通过不代表所有自然语言的路由都已被确定性保证。此修复没有替换全部关键词检查，没有改动 HTTP 400 响应日志、并发锁或线上部署流程。
