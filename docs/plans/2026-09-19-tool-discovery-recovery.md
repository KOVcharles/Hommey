## 实施

1. 新增 `agent_runtime/capabilities.py`：每次调用模型时，从当前原生工具 schema 生成 system prompt 中的名称、用途、参数摘要。主模型同时看到由 `PROFILES` 和业务工具注册表生成的角色能力映射，明确哪些工具通过 `delegate` 使用。目录只在调用时生成，不新增 checkpoint/payload 字段，不将目录反复写入历史。
2. `read_skill` 返回实际 `available_resources`，缺少文件时返回 `SKILL_RESOURCE_NOT_FOUND` 和可选路径。`query-info` 没有参考文件时明确返回空列表；另一个 Skill 名应填写 `name`，不应填写 `resource`。资源必须在枚举出的 references 文件内，路径越界仍无法读取。上下文压缩保留参考文件目录。
3. 区分 `UNKNOWN_TOOL` 和 `TOOL_NOT_AVAILABLE`，返回当前 `available_tools`，提示模型自行修正；主模型直接调用子角色工具时提示对应委派角色。独立查询批次中的一个错误名称不再取消其他有效查询。写入和终止工具的独占要求保留。
4. 记忆与出行子任务取消“第一轮唯一查询、第二轮只能回读、第三轮强制报告”的阶段限制。允许在配置的子任务轮数内发现问题、补查、回读并修正报告；最后一轮用于报告。原有查询去重、角色权限、来源验证、时间/轮数/调用预算保留。制度检索的阶段限制本次没有改动。
5. 工具/参考文件发现错误仍消耗总轮数和时间预算，但不再累计业务 `no_progress` 导致提前吞掉未完成需求；也不清除已有失败计数。主循环和断点恢复使用同一个可用工具计算函数，避免提示与执行检查分叉。
6. 删除子任务 payload 的重复 `request` 字段：原始输入已在 `conversation`，当前委派由 `task` 表达。明确当前用户的其他需求也不自动属于这个子任务。同角色的多项查询可合并委派，已有结果时只补缺项。
