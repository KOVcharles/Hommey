# 正文流式输出改造

## 改造前与改造后

之前的 `/chat/stream` 已通过 NDJSON 实时传输任务进度，但模型调用使用 `stream=False`。普通正文在生成完后，每 18 字、每 10 毫秒分块发送；结构化回答一次返回。因此正文通常在等待一段时间后整体出现。

现在模型使用真实 streaming。Python 收到主 Agent 的正文增量后立即产生 `chunk`，Spring 和 Nginx 沿用原来的流式转发，前端逐段累加、渲染。SDK 返回的是累计快照，适配层只发送相对上一快照新增的文字，重复的用量快照不会重复显示正文。

这次复用同一个模型和同一次模型请求，不增加最终回答的额外模型调用。工具编排、数据库归属、权限接口和业务事务保持原有约定。

## 输出与工具执行约定

| 内容 | 处理方式 |
| --- | --- |
| 主 Agent 正文 | 收到文字增量立即发送；不暴露模型的 thinking 内容 |
| 工具参数、子任务报告 | 缓存到最终快照，再按原生 `raw_input` 进行完整 JSON 校验；通过校验后才能执行工具 |
| 正文后出现工具调用 | 发出 `response_reset`，撤回尚未完成的正文草稿，继续任务进度；工具参数不会变成用户可见的正文 |
| 结构化回答、天气、行程和信息表单 | 完成校验后完整渲染，避免半截对象破坏卡片 |
| 固定提示、缓存重放 | 直接发送现有完整内容，不用延时分块模拟生成 |
| 流式失败 | 撤回未完成草稿，沿用经过验证的降级结果或现有错误提示 |
| 取消或前端断连 | 取消请求任务并关闭模型生成器；前端收到停止事件时撤回未完成草稿、显示停止提示 |

不是每一种回答都会逐字出现。无需模型生成的固定提示和已保存回答，本来就已经完整；结构化卡片继续完整交付。模型生成普通正文时才有真实增量。

AgentScope 的 `stream_tool_parsing=False` 禁止在每个 token 上修补工具 JSON。SDK 在流结束后生成的解析对象仍须通过 `raw_input` 的严格校验，截断后被 SDK 修补的对象不能授权业务写入。

## 会话保存与前端完成状态

- 用户看到的增量属于尚未完成的草稿。Supervisor 和原有 Web 处理链在生成完成后保存完整回答，不将每个 token 写入数据库。
- 完成后返回的正文与已经传输的正文相同时，不再发送一次完整回答，避免重复。
- 最终结果是卡片、降级回答或经过处理的不同正文时，先发 `response_reset` 清除草稿，再交付最终结果。
- 前端必须收到 `done` 才把本次请求视为完成。连接直接结束而没有 `done` 时，撤回未完成正文，并提示连接中断、可重试。
- 原有请求编号、幂等重放与取消栅栏继续生效；停止生成不撤销此前已合法提交的业务操作。

## 文件改动

| 文件 | 改动 |
| --- | --- |
| `agent_runtime/model_client.py` | 启用 streaming，提取累计快照中的正文增量；工具参数严格校验、草稿重置、生成器关闭 |
| `agent_runtime/engine.py` | 仅将主 Agent 正文增量接入现有 progress 回调，子任务参数不送到页面 |
| `webui_new/manager.py` | 同步转发正文增量，核对最终正文，移除模拟分块；卡片和降级结果替换草稿 |
| `webui_new/static/app.js` | 消费 `response_reset`；取消/错误时撤回草稿，检查 `done`，保留既有逐段 Markdown 渲染 |
| `tests/test_native_streaming.py` | 增加有暂停点的增量测试、工具完整性、断连、取消、保存与重放、卡片替换，以及真实已安装 SDK 的严格参数测试 |
| `tests/test_chat_stream_delivery.cjs` | 用暂停的数据流执行实际前端接收函数，验证首段渲染、草稿撤回、没有 done 的断流、错误、取消和卡片替换；无需浏览器依赖 |
| `tests/test_supervisor_context_bounds.py` | 更新 streaming 开关断言，继续要求原始工具 JSON 完整，禁止 SDK 修补对象授权操作 |
| `.github/workflows/backend-ci.yml` | 将新测试加入回归与格式检查；检查 main 和 codex 分支的推送 |

Spring Controller、WebClient 和 Nginx 已支持 NDJSON 转发，这次不修改它们的转发逻辑。更新静态页面需重新构建 backend 镜像，更新 Python 需重新构建 AI 镜像。

## 验证范围

离线测试必须证明第一段内容在模型仍被暂停时已经到达，避免只通过检查 `Content-Type` 来判断是否流式。此外覆盖累计快照去重、工具参数完整前不返回、截断参数拒绝、模型异常重置、取消关闭连接、最终内容保存与幂等重放、结构化卡片替换草稿。

部署后还需观察真实接口从首段正文到 `done` 的到达时间，并确认会话中的最终正文与传输结果一致。完整差旅卡片、模型推理模式以及较慢的外部检索仍可能在正文出现前产生等待，任务进度会继续推送。
