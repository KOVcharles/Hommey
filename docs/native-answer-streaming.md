# 正文流式输出改造

## 改造前与改造后

之前的 `/chat/stream` 已通过 NDJSON 实时传输任务进度，但模型调用使用 `stream=False`。普通正文在生成完后，每 18 字、每 10 毫秒分块发送；结构化回答一次返回。因此正文通常在等待一段时间后整体出现。

现在模型使用真实 streaming。Python 收到最终答复阶段的正文增量后立即产生 `chunk`，Spring 和 Nginx 沿用原来的流式转发，前端逐段累加、渲染。SDK 返回的是累计快照，适配层只发送相对上一快照新增的文字，重复的用量快照不会重复显示正文。

普通文字回答分为工具编排与最终正文两个阶段，复用同一个模型。编排阶段通过原生 `finish(kind="text")` 明确交出控制权，再发起 `tools=[]`、`tool_choice="none"` 的正文请求。相较于工具和正文混用的单次请求，普通文字回答增加一次短的交付决策调用；调用仍计入既有预算，首字等待和模型费用可能增加。结构化卡片沿用既有交付路径。

## 修复编排文字短暂闪现

最初实现会立即转发主 Agent 的 text，等后续出现 tool_use 时再撤回草稿。模型可能先输出“我来查询一下……”，隔一段时间才输出工具调用，所以页面会短暂显示过程说明。

修复后，任何提供了工具的模型调用都不触发正文回调，包括工具调用出现前的文字和非流式兼容响应。主循环要求原生工具调用，调用 `finish(kind="text")` 后才允许发送正文。该入口不接受 `question`、`result_ids` 或 `reuse_reasons`，避免将预先生成的答案塞入工具参数模拟流式。正文调用携带已配对的 finish 工具回执、原对话和现有证据，禁止再次执行工具；空白回复或意外工具调用会被拒绝。

正文提示要求直接回答问题，不输出工作计划或查询前言；协议层忽略 thinking 内容。隔离依赖明确的执行阶段，不依赖“我来”等关键词，也不通过延迟显示来猜测后续是否会调用工具。兼容端点若忽略 required 并返回纯文字，原有完整响应兼容路径仍保留，但不会逐段发送编排草稿。

## 输出与工具执行约定

| 内容 | 处理方式 |
| --- | --- |
| 工具编排阶段文字 | 仅留在后台上下文，不产生正文增量，也不先显示后撤回 |
| 最终答复正文 | 在禁止调用工具的专用请求中收到增量立即发送；忽略 thinking 内容 |
| 工具参数、子任务报告 | 缓存到最终快照，再按原生 `raw_input` 进行完整 JSON 校验；通过校验后才能执行工具 |
| 正文请求违规返回工具调用 | 不执行工具，拒绝答复并清理已发送的草稿，沿用有界修复与降级路径 |
| 结构化回答、天气、行程和信息表单 | 完成校验后完整渲染，避免半截对象破坏卡片 |
| 固定提示、缓存重放 | 直接发送现有完整内容，不用延时分块模拟生成 |
| 流式失败 | 撤回未完成草稿，沿用经过验证的降级结果或现有错误提示 |
| 取消或前端断连 | 取消请求任务并关闭模型生成器；前端收到停止事件时撤回未完成草稿、显示停止提示 |

不是每一种回答都会逐字出现。无需模型生成的固定提示和已保存回答，本来就已经完整；结构化卡片继续完整交付。模型生成普通正文时才有真实增量。

AgentScope 的 `stream_tool_parsing=False` 禁止在每个 token 上修补工具 JSON。SDK 在流结束后生成的解析对象仍须通过 `raw_input` 的严格校验，截断后被 SDK 修补的对象不能授权业务写入。

## 会话保存与前端完成状态

- 用户看到的增量属于尚未完成的草稿。Supervisor 和原有 Web 处理链在生成完成后保存完整回答，不将每个 token 写入数据库。
- 完成后返回的正文与已经传输的正文相同时，不再发送一次完整回答，避免重复。
- 最终结果是卡片、降级回答或经过处理的不同正文时，先发 `response_reset` 清除草稿，再交付最终结果。
- 前端必须收到 `done` 才把本次请求视为完成。连接直接结束而没有 `done` 时，撤回未完成正文，并提示连接中断、可重试。
- 原有请求编号、幂等重放与取消栅栏继续生效；停止生成不撤销此前已合法提交的业务操作。

## 验证范围

离线测试分别暂停工具编排和最终正文：在“我来查询……”已生成、后续工具调用尚未出现时，前端收到的正文必须为零；在最终正文仍未结束时，首段正文必须已经到达。同时覆盖累计快照去重、工具参数完整前不返回、截断参数拒绝、模型异常重置、取消关闭连接、最终内容保存与幂等重放、结构化卡片替换草稿。

部署后还需观察真实接口从首段正文到 `done` 的到达时间，并确认会话中的最终正文与传输结果一致。完整差旅卡片、模型推理模式以及较慢的外部检索仍可能在正文出现前产生等待，任务进度会继续推送。
