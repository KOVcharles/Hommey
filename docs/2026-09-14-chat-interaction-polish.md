# 聊天交互与行程卡片修整

本次围绕聊天等待、行程补全、卡片归档和小屏交互调整。

- Hommey 标识贯穿等待、进度、文本回复和结果卡片；卡片内重复标识在聊天中隐藏。
- 进度默认呈现为轻量状态行，按需展开。重复尝试合并为一个用户动作，保留最后状态；不显示内部说明、逐步耗时和重复失败日志。执行记录本身不变。
- 行程表单通过原聊天接口提交。完整内容仍进入记忆与运行时，使用 `content_type=trip_submission` 标识，实时聊天和历史回放都隐藏字段长文本。
- 每张补全卡绑定生成它的助手请求编号。任何后续消息使其失效；刷新时按持久化消息顺序恢复只读状态。服务端在已有用户锁内、消息或行程写入前校验所属会话和卡片版本。
- 旧卡替换成可展开的只读快照，不保留可提交的表单控件。无法确定来源的旧记录也只读。
- 提交接收后发生可重试错误时，保留填写快照和输入框草稿，提供同一请求、同一内容的重试；新消息会撤去旧重试入口。服务端拒绝借重试修改提交内容。
- 保留用户手动展开的进度状态，提供键盘焦点与减少动画适配；查看历史时停止自动跟随。修复手机端聚焦造成的横向偏移和品牌裁切。

验证：81 项相关 Python 回归通过，Node 进度组件检查通过，既有日历浏览器回归通过。新增 `tests/check_chat_polish_ui.py` 使用生产页面及脚本、确定性 HTTP 数据，在 Edge 中覆盖桌面、小屏、深色、隐藏提交、只读归档、失败重试、草稿保留和流式回复期间的滚动。截图位于 `.codex-resume-work/chat-polish-qa/`。
