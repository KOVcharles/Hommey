# 车票日期补充误触发行程收集 Bug 记录

> 编号：BUG-2026-08-17-01<br>
> 发现日期：2026-08-17<br>
> 状态：车票路径已修复；通用 `event_collection` 语义状态问题待后续加固

## 1. 用户现象

对话如下：

```text
用户：帮我查一下定南到重庆的车票
助手：请告诉我出行日期，例如「明天」或「8月20日」……
用户：明天的
助手：重庆差旅信息 / 已整理好行程安排
```

用户只是在补充车票日期，界面却显示已经完成重庆差旅行程安排；此前合法的
12306 空结果还可能被错误展示为“12306 余票接口暂不可用”。

## 2. 实际执行证据

2026-08-17 09:35—09:36 的运行日志表明：

1. 第一轮只执行了 `train_query`。
2. 第二轮“明天的”重新经过意图识别，随后只执行了 `event_collection`。
3. 第二轮没有执行 `plan_trip`、政策查询、天气查询或完整的行程规划 DAG。

因此，页面上的“已整理好行程安排”不是完整规划真的执行完毕，而是独立信息收集
结果被展示层错误包装成了已完成行程。

## 3. 根因

### 3.1 车票追问不是可恢复的结构化暂停

缺少日期时，`train_query` 返回了一段要求补充日期的普通文本，但没有创建一个
可在下一轮恢复的“待补充车票日期”状态。下一条消息会作为新请求重新识别意图。

### 3.2 日期型短回复被误判为行程收集

“明天的”本身没有“车票、车次、火车、高铁”等意图锚点。意图提示又规定：当系统
正在收集出差信息时，日期片段应路由到 `event_collection`。模型据此把车票日期补充
误判成了出差事项补充。

### 3.3 车票上下文被当成了行程事实

`event_collection` 可以读取本会话最近的用户消息。它从上一轮车票问题中提取了
“定南、重庆”，再从本轮提取“明天”，因而生成了一张部分行程卡，尽管用户从未
发起公司差旅规划。

### 3.4 执行成功与信息完整被混淆

`evaluate_trip_intake()` 会确定性检查出发地、目的地、出发日期、行程时长和出差目的。
本次缺少行程时长和出差目的，`planning_ready` 应为 `false`。

完整的 `itinerary_planning` 工作流会在 `planning_ready=false` 时暂停后续节点；但本次
直接调用的是独立 `event_collection`，没有进入该工作流的暂停门。Agent 无异常返回后，
任务技术状态仍是 `success`，展示层又把技术成功误写成“已整理好行程安排”。

## 4. 本次修复

- 用户未指定车票日期时，按 `Asia/Shanghai` 的当天直接查询，不再仅因缺日期追问。
- 对“今天、明天、后天、周几、具体日期”等日期型短回复增加上下文续接：只有紧邻的
  上一条用户消息明确为车票查询时，才继承原路线并继续走 `train_query`。
- 非车票上下文中的日期短回复不继承车票意图，仍交由正常意图识别处理。
- 12306 返回合法空列表时解释为“未查询到直达车次”，不再当成上游接口故障。
- train-query Skill 文档同步规定“缺日期默认今天”。

## 5. 验收结果

- 车票、12306 后端及意图守卫相关回归：`61 passed`。
- 真实查询验证：
  - “定南到重庆的车票”查询日期为 `2026-08-17`；
  - 后续“明天的”继承同一路线，查询日期为 `2026-08-18`；
  - 两次合法空结果均显示“未查询到直达车次”。
- 双 Uvicorn worker 重启后 `/readyz` 通过，Redis、PostgreSQL/pgvector 与 RAG worker
  均处于 ready 状态。

## 6. 剩余风险与后续建议

本次修复阻断了车票场景的复现路径，但没有改变独立 `event_collection` 的通用语义：
未来若其他模糊短回复被错误路由到该意图，仍可能出现 `planning_ready=false`、任务状态
却为 `success` 的不一致。

后续应统一以下约束：

1. 无论 `event_collection` 是工作流节点还是独立意图，只要 `planning_ready=false`，都进入
   `WAITING_USER` 或等价的“继续收集”状态。
2. 展示层根据 `planning_ready` 和缺失字段渲染，不得仅凭任务技术状态 `success` 宣布行程完成。
3. 将“等待补充信息”建模为带原始意图、已确认槽位和缺失槽位的持久化暂停，而不是普通文本。
