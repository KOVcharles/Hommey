# 差旅行程选择卡片交付记录

日期：2026-09-12

## 问题与改动

原界面按内部任务输出制度、记忆和行程摘要，用户需要的车次、准确地点及附近酒店没有形成可操作的结果。通用事实网格把长文本和来源 ID 堆在一起，无法帮助用户做选择。

本次将现有行程收集、12306、高德和个人偏好接成连续流程：

1. 收齐出发地、目的地、日期等基本信息后展示真实车次；缺少会议地点时仍可查看车次。
2. 在目的地城市内搜索和选择高德地点，显示名称、行政区和地址。服务端过滤候选结果，提交时重新查询 POI 并校验城市。切换目的地、编辑或清空地点时使旧选择失效；过期异步响应不能覆盖新城市结果。
3. 以已验证地点为中心查询附近酒店，补充保存的品牌偏好检索，按品牌匹配、距离和评分排序。过滤大堂、礼宾等附属设施并去重。
4. 独立呈现车次时间、车站、跨日到达、席别余量及酒店距离和推荐原因。支持有票筛选、地图入口、地点补充和失败重试。制度详情默认折叠。
5. 将主流程写入 plan-trip skill，地点选择和候选展示规范按需读取 references。运行时支持读取受限引用路径，并将首次读取引用计入有效进展。

结构化表单与普通聊天均接入选择卡片。地点选择通过现有聊天提交链路保存，并保留用户排除的查询项目。天气及到达车站至会议地点的参考交通仅在明确请求时补充。

## 验证

- 相关 Python 回归测试：170 通过，1 个默认跳过的真实模型测试。
- 单独开启真实模型测试：通过；模型读取规划 skill、核对当前行程后接续选择卡片，用时约 11.9 秒，无重复行程写入。该测试采用隔离存储和业务接口样本，避免改动员工数据。
- 独立真实接口联调：北京至重庆查询返回 12 个车次；重庆国际会议展览中心附近返回 4 家汉庭酒店，距离约 603、1410、2139、2387 米。没有写入员工行程。
- 浏览器验证：使用实际卡片组件和真实接口快照检查桌面、手机、深色主题、车票筛选、地点键盘选择、城市切换后的过期响应、编辑失效和无结果状态；通过，无横向溢出。已有日期选择器回归通过。
- JavaScript 语法、已有车次渲染及执行过程 DOM 测试通过，diff 空白检查通过。
- 本机 hommey-app 已重启并通过健康检查；未部署远端。

没有把只读预览测试称为完整登录用户端到端测试；本次分别验证了真实接口、运行时、提交校验和浏览器组件。

## 使用与边界

刷新本机聊天页面，发起或继续出差规划。基本行程完整后查看车次，在会议地点选择器中搜索并选择准确地址，再提交以获得附近酒店。

只读界面预览：<http://localhost:8000/static/design-demos/trip-choices.html>。预览使用联调时的公开数据快照，不提供登录查询或实际提交；真实业务操作在聊天页面完成。

- 12306 返回的余票是查询时状态，未提供的票价不会编造。选项卡不办理订票。
- 高德酒店 POI 不提供实时房态；参考消费不是房晚报价，也不能据此判定符合住宿标准。
- 未提供会议时间时，不承诺列车能够赶上会议。参考市内交通明确标注其起点车站。
- 品牌和席别偏好不代表公司批准的差旅等级；制度缺失时仍需核实。
- 查询异常会保留其他成功结果并显示下一步，不将内部执行日志作为最终行程。
