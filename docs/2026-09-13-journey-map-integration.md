# 会场与酒店地图接入记录

## 用户流程

1. 普通聊天发起行程后，在首次行程确认卡片内搜索高德地点。基本信息完整但没有确认地点时，先显示地点确认卡片。快捷行程表单也要求选择准确地点并可预览地图。
2. 选择范围严格受目的地城市约束；修改城市或编辑地点使原选择失效。提交时仍按 POI ID 向高德复核城市和坐标，不信任客户端填写的名称或坐标。
3. 确认行程后查询真实车次，以及会场附近按偏好排序的酒店。结果卡片将会场和酒店标记放在同一地图上，酒店列表与地图联动。
4. 在结果卡片展开“修改地点”，选择新会场并确认，重新走提交、校验、更新行程、查询车次和酒店流程，追加新的结果卡片。旧卡片继续保留对应旧会场的结果，不混用新旧酒店。

## 实现与展示

- 可复用地图组件支持小尺寸定位针、固定大小的酒店编号、滚轮和加减按钮平滑缩放、展开地图及地图链接，适配桌面与手机、深色主题。
- 地图接入现有高德 Web 服务，通过已鉴权的后端地图接口动态加载任意已验证 POI 的底图；正式代码不引用 Demo 的固定地点或地图图片。前端不接触高德 Key。
- 地图按可见性加载，底图缓存有过期时间和容量上限。切换地点取消旧请求，移除卡片释放图片 URL 和动画。地图失败时仍保留文字地点及酒店信息。
- 车次列表收紧高度。会场修改默认折叠。酒店列表突出名称、品牌匹配、距离和评分，详细地址随地图选择展示；不将高德参考消费冒充房价。
- 地点计入行程确认进度。明确排除酒店查询时，不用会议地点阻塞车次查询。
- 更新 plan-trip skill 及地点选择引用文档，指导 agent 按新流程处理。

## 验证

- 行程、运行时、地图接口与相关回归：175 通过、1 个真实模型测试默认跳过。
- 单独开启真实模型测试：通过，16.55 秒；模型读取 skill、核对当前行程后返回地点确认卡片，没有重复写行程。使用隔离测试存储。
- 两个真实会场分别查询：重庆国际会议展览中心、重庆悦来国际会议中心，各返回 12 个车次和 4 家附近酒店；真实地点建议、地图图片接口通过。仅查询公开数据，不写员工行程。
- 浏览器实际组件检查通过：首次填全表单并选地点、修改目的地清除旧 POI、选择后地图加载、生成结果卡片、修改会场并追加不同酒店的新卡片、手机无横向溢出、深色主题。原日期选择器与车次卡片交互回归通过。
- 服务端测试确认地图接口需要登录、跨城市 POI 被拒绝、底图缓存生效及错误信息不包含密钥；修改会场后新酒店只来自新 POI。
- Web 错误响应、鉴权路由及安全回归：45 通过。上述离线回归合计 220 通过，真实模型测试另行通过。

浏览器流程测试使用真实接口快照模拟提交完成；服务端提交校验和查询更新另外通过运行时集成测试验证，未宣称使用员工登录账号完成整条线上业务测试。

## 使用入口与范围

本机正式聊天页面刷新后生效。独立流程预览：<http://localhost:8000/static/design-demos/journey-flow.html>，预览使用公开数据快照，不保存行程。

当前使用动态请求的高德静态底图，支持 12—15 级连续缩放，不支持自由拖动。后续可在配置 Web 端 JS API Key 后替换底图加载实现，保留现有城市校验和查询流程。酒店实时房态、房晚价格和实际预订未包含在本次接入中。
