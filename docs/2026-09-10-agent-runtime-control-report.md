# AgentRuntime 执行控制修复报告（第一版）

日期：2026-09-10。

本版把成功判定、写入、证据校验、重复抑制、执行终止和恢复资格放在运行时代码中。模型仍负责自由文本理解和方案内容生成，不能自行决定空报告算成功、重复查询是否执行、失败后无限重跑。

## 本版行为

### 行程数据和写入

现有补充卡片把字段编码为“从北京出发，目的地：南京，2026-09-11出发，出差2天，出差目的：参加会议”。新增严格的卡片文本适配器直接解析这些字段，经过原文与字段校验后使用已有事务回执写入；模型不可用也不再丢失这类完整表单。部分字段提交先保存并返回补充表单。

此适配器只接收完整匹配的已知字段序列，不吞掉混合请求、重复字段和模糊日期。自由文本仍由 trip_context 提取，但必须返回类型化 TripData，且在报告阶段验证原文依据。合法提案由运行时提交；模型之后重复 apply_changes 返回已提交结果，不重复写入。

空行程上的 new 规范化为 update；替换现有行程仍要求明确用户依据。未知字段不允许入库，null 不当作清空操作。

### 报告结构

| 角色 | 运行时约束 |
|---|---|
| trip_context | TripFields、field_sources、trip_action；拒绝空成功和“有来源却漏字段” |
| policy_rag | 逐项 findings、具体结论、适用条件及引用 |
| memory | findings 与偏好变更分字段表达；新变更必须有本轮原文，重复已有偏好不会转成写操作 |
| travel_info | findings 为已核实交通/天气/酒店/通勤事实，保留逐项引用 |
| trip_planner | itinerary.days 的日期、活动列表有明确类型及大小界限 |
| compliance | verdict、checks、逐项状态、理由与引用；确定结论必须有检查和政策依赖 |

检索事实中的不存在来源会被拒绝。未知或尚未读取的条目不会作为确定结论交付；剔除这些条目时用运行时摘要替换原摘要，把缺项列入 missing_info，保留其他已核实条目。原始资料不进入主 Agent 简报；主 Agent 接收有限的事实、条件、未知项和来源编号。

### 错误协议与执行终止

工具错误保留兼容用 error 文本，并增加 failure：code、message、retryable、next_action、fields、violations。Pydantic 字段错误包含规则和边界，不回显用户输入。关键错误包括 EMPTY_TRIP_REPORT、MISSING_TRIP_FIELDS、MISSING_EVIDENCE、UNREAD_EVIDENCE、UNKNOWN_EVIDENCE、DUPLICATE_CALL、ROLE_TASK_LIMIT、TRIP_INCOMPLETE、SOURCE_SIZE_LIMIT。

| 控制项 | 默认行为 |
|---|---|
| 相同查询/相同来源页 | 参数经类型模型补齐默认值后计算指纹；并发或后续重复均不再次执行 |
| 偏好搜索同义词 | kind=preferences 实际读取同一行，query/limit 不形成不同查询 |
| 相同已完成任务 | 返回已完成结果，不新建子任务 |
| 相同失败任务 | 本轮不重跑，要求交付其他结果 |
| 改写任务绕过限制 | 同行程版本、同角色默认最多两项任务 |
| 无进展 | 连续三轮没有实质进展，主 Agent 由运行时收尾 |
| 子报告修复 | 最多两次报告错误，即一次修复机会 |
| 纯整理/规划/合规 | 只输出结构化报告，最多一次修复；不再探索性读取指南 |
| 记忆/出行阶段 | 第1轮查询或直接报告，第2轮回读/报告，第3轮报告，第4轮仅修复报告 |
| 政策阶段 | 第1轮查询，随后回读，第4轮报告，第5轮仅修复 |
| 整轮期限 | 默认60秒，配置限制在5至120秒；到期取消异步执行并生成部分交付 |
| 单条/整轮新来源 | 单条超过50,000序列化字符，或新接收来源累计超过200,000字符，在写入检查点前拒绝 |

失败交付只选择当前版本、未丢弃、未过期的已验证结果，以及实际已提交的变更。没有可交付资料时明确说明；行程收集失败且缺字段时返回补充表单。降级结果持久化 outcome=degraded 和 stop_reason，同请求重试返回相同响应，避免再次放大耗时。

表单任务已有有效规划产物时，运行时直接交付，不再等主模型额外 read_result/finish；用户明确要求合规检查时保留后续检查。规划漏传依赖ID时补齐当前有效政策和出行结果。

### 检查点和“继续”

保留原有 pending tool call 与原子写入回执，新增 checkpoint_version=2、work_items 和 control。work_items 记录角色、任务、输入版本、依赖、状态、尝试次数、结果 ID、错误码；每个子任务另外持久化查询指纹、已读来源、无进展/报告错误计数。

“继续”从同用户、同会话的前次检查点复用已完成的结构化结果，而非仅给摘要后重新查询。只复用版本相符且未被丢弃的成功/部分结果；出行来源维持15分钟有效期；未提交的历史变更不自动重放。旧版检查点不自动升级为已验证结果。本版不是任意历史自然语言指代的完整工作流恢复器。

协议 ID 的脱敏误伤已修复，正文中的隐私信息仍脱敏。进度事件补齐 intent/display/task_id，前端可显示真实专业任务名称。

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_supervisor_control.py tests/test_supervisor_runtime.py tests/test_supervisor_context_bounds.py tests/test_single_runtime.py tests/test_trip_intake_experience.py tests/test_quick_trip.py tests/test_runtime_thinking.py -q --disable-warnings

```

真实模型测试使用当前配置的 deepseek-v4-flash、合成政策/偏好/车次/天气和隔离的 FakeStore，不修改生产用户数据。该测试检验模型与运行时的协议配合，不能替代 PostgreSQL、真实 RAG、12306 和浏览器端到端验证。测试保留“正常路径必须正常完成”的断言，失败降级不会被算作成功。

离线最终结果：98 passed，1条既有 pytest-asyncio 配置弃用警告；JavaScript 语法检查和 git diff --check 通过。新增失败注入断言覆盖空成功、字段遗漏、未经授权替换、重复/并发查询、默认参数归一化、无进展、截止取消、局部交付、继续复用、隐私脱敏和超大资料拒绝。

## 已知边界

- Docker Engine 当前未运行；本地 WebUI 测试初始化数据库时发现 DSN 格式问题，数据库/路由联调尚未完成。没有修改凭据或重启生产服务。
- 完整规划的内容质量仍依赖模型，工具来源存在和类型正确不等于所有语义推断必然正确；需要真实业务数据评测。
- 保留主/子模型消息作为诊断及同请求恢复材料，尚未将全部原始证据迁移到独立外部工件存储。
- 卡片目前仍使用既有文本编码适配，后续可迁移为独立类型化 HTTP 字段协议，减少前后端编码耦合。
- 取消、所有权丢失和数据库写入失败继续遵守写入隔离；不能在数据库不可用时声称已保存。
