# 输出排版与补充信息卡片：修改报告

本版已在当前工作区完成：增加 AI 可选择调用的补充信息表单，统一普通回答与结果卡片的 Markdown 渲染，并补上中文标点附近的加粗兼容。未新增数据库表。

## 1. 排查结论

这次发现的显示问题有三个来源：

1. **普通聊天仅用正则处理加粗和换行。** 标题、表格、嵌套列表、引用、链接和代码块没有完整解析。流式回答与历史回答共用这段代码，因此两处都会受影响。
2. **结果卡片的许多字段直接写入 `textContent`。** 摘要、条目说明、制度适用条件中的 `**` 会原样出现。另一个正文函数虽然会删除部分标记，却同时丢掉强调语义；不同展示路径的效果不一致。
3. **中文标点存在额外问题。** 标准 Markdown 的强调边界规则会把 `**职称：**正高`、`**正高（教授）**人员` 留成纯文本。只换一个标准解析器，还不能解决这类中文输出。

## 2. 用户现在可以怎样补充信息

新增 `request_information` 工具，由主 Agent 根据当前缺失信息选择调用。调用后结束当前轮次，展示 `information_request` 卡片，状态为 `waiting_input`。

| 内容 | 界面行为 |
| --- | --- |
| 单选，2～4 个常见选项 | 直接点击选项按钮 |
| 单选，5～8 个常见选项 | 下拉框选择 |
| 多选 | 可同时选中多个选项 |
| 选项未覆盖的答案 | “自行填写”展开文本输入框 |
| 日期 | 浏览器日期选择器 |
| 普通文本 | 简短文本输入框 |
| 不想操作表单 | 可以继续在聊天输入框直接回复 |

每张卡片最多 5 个字段，每道选择题最多 8 个常见选项。模型不能预选用户的答案；必填项未完成时不能提交，选填项可以跳过。“自行填写”被选中后，也必须实际填写内容。

用户选好后点击“确认并继续”，界面将选择转成自带字段名称的消息。例如：

```text
补充信息（确认适用的差旅条件）：
人员类别：教职工
职称：正高
经费来源：科研经费
```

这样后续模型收到完整条件，不需要猜测“第二项”指什么。原有行程专用表单继续负责出发地、目的地、工作地点等流程；通用表单可以用于人员类别、职称、经费来源等任务条件。

本版选项由 AI 根据问题生成，并非硬编码的统一身份字典，也不代表已经核实的报销资格。一次选择仅补充当前对话，不会因为提交卡片而自动写入长期个人资料。

## 3. 会话与失败处理

- 复用现有聊天接口、请求 ID、会话锁及持久化流程。`intake_request_id` 现在也可关联通用卡片，没有增加第二套聊天接口。
- 卡片只能在所属会话、当前有效轮次提交；旧卡片、其他来源 ID 和修改了正文的重试会被拒绝。
- 提交期间锁定控件，避免重复点击。提交前失败保留卡片内的值；请求接受后发生可重试错误，沿用原有的相同正文／相同请求 ID 重试入口。
- 表单提交保留输入框里尚未发送的草稿，也不会附带草稿附件。
- 已提交或被后续消息替代的卡片变成只读折叠记录。刷新／重新打开会话时，可恢复提交内容与归档状态。
- 后端保存 `form_submission` 标记，界面用卡片内的提交摘要展示，避免再复制一大段用户消息。普通手动回复仍正常显示。
- 顺便修复了无来源 ID 的历史卡片可被字符串 `"None"` 匹配的边界问题，使后端校验与前端只读行为一致。

## 4. 输出排版的变化

新增共享渲染入口 `HommeyMarkdown.render`，用于聊天回答、流式文本、历史回答、通用结果卡片、制度正文及信息卡片说明。

支持标题、加粗、斜体、删除线、列表、引用、表格、链接、行内代码和代码块。任务清单显示勾选状态；表格超出宽度时在表格内部横向滚动。布局、字号和颜色复用现有浅色／深色主题。

中文加粗兼容通过解析器的行内扩展实现：在配对、包含中日韩文字的加粗内容中兼容标点边界。代码片段、转义星号、三重强调仍按各自语义处理；尚未闭合的标记不会被凭空补全。流式输出在闭合标记到达前，仍可能暂时显示未完成的标记。

用户自己发送的消息继续按原文显示，以免输入内容被误改。结果卡片保留原有交通排序、折叠、制度金额强调等行为。

渲染使用本地固定版本 Marked 18.0.14 与 DOMPurify 3.4.16，不依赖浏览器访问 CDN。已校验 npm 包的 SHA-512，保存浏览器文件的 SHA-256 和原始许可文本。Marked 负责解析，DOMPurify 使用限定标签／属性清单清理结果；脚本、事件属性、表单、iframe、图片及危险链接不进入回答 DOM。外链只允许 HTTP(S)，并加上隔离属性。依赖未加载时降级为纯文本。

实现依据：[Marked 官方说明](https://marked.js.org/)、[Marked 扩展 API](https://marked.js.org/using_pro)、[DOMPurify 官方项目](https://github.com/cure53/DOMPurify)。Marked 官方明确说明，解析器本身不负责清理不可信 HTML，因此这里将清理步骤放在公共渲染入口。

## 7. 运行状态与范围

代码与报告已保存。本机 `hommey-app`、PostgreSQL、Redis 等常驻容器在本轮开始时就处于停止状态，本轮没有启动或部署这些服务；测试容器均已退出。真实浏览器检查使用实际 HTML、CSS、JS 配合模拟接口，实际模型检查使用合成数据，没有写真实业务资料。

要在正常聊天入口体验，需要按项目现有方式启动应用及依赖，让后端加载新工具和提示词，浏览器刷新加载新静态资源。修改后的资源已经更新缓存版本。

本版没有实现字段之间的条件联动、统一身份枚举和注册时个人资料表。存在前置条件时，AI 可以分轮询问；例如先确认是否学生，再询问适用的学生类别。表单是否出现仍由模型根据问题选择，实际模型的一次通过只能证明工具调用与参数兼容，不能保证所有问题都会采用表单。
